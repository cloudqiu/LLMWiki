在上一篇文章中，我们学习了 Rust 的 `use` 与 `pub` ，了解了如何导入模块、控制访问权限以及设计公共 API。

当一个 Rust 项目开始对外提供函数、结构体、枚举和 Trait 后，仅仅让代码能够编译还不够。使用者还需要知道：

- • 这个函数有什么作用？
- • 参数分别表示什么？
- • 返回值是什么？
- • 什么情况下会返回错误？
- • 应该怎样调用？
- • 是否可能发生 `panic` ？

Rust 提供了一套内置文档工具：

```
rustdoc
```

配合 Cargo，可以直接从源代码中的文档注释生成 HTML API 文档。

常用命令是：

```
cargo doc
```

本文将介绍：

- • 普通注释与文档注释的区别
- • `///` 与 `//!` 的使用
- • 文档中的 Markdown
- • 代码示例与文档测试
- • `cargo doc` 常用命令
- • 函数、结构体和模块文档写法
- • Rust 项目文档最佳实践

## 普通注释与文档注释

Rust 普通单行注释使用：

```
// 普通注释
```

多行注释使用：

```
/*
这是多行注释
*/
```

普通注释主要供代码维护者阅读，不会自动出现在 API 文档中。

例如：

```
// 计算两个整数的和
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

执行：

```
cargo doc
```

这段普通注释不会成为函数的公开文档。

要生成 API 文档，需要使用文档注释。

---

## 使用 /// 编写项目项文档

`///` 用于说明紧跟在它后面的代码项，例如：

- • 函数
- • 结构体
- • 枚举
- • Trait
- • 字段
- • 常量
- • 模块

示例：

```
/// 计算两个整数的和。
///
/// # 参数
///
/// - \`a\`：第一个整数
/// - \`b\`：第二个整数
///
/// # 返回值
///
/// 返回 \`a\` 与 \`b\` 的相加结果。
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

生成文档后，函数名称、说明、参数和返回值都会显示在 HTML 页面中。

文档注释最终会按照 Markdown 格式渲染。

---

## 使用 //! 编写模块文档

`//!` 用于说明当前模块或当前 Crate。

例如，在 `src/lib.rs` 文件顶部写：

```
//! 一个简单的数学工具库。
//!
//! 该库提供整数加法、减法和安全除法功能。
//!
//! # 示例
//!
//! \`\`\`
//! use math_utils::add;
//!
//! let result = add(10, 20);
//! assert_eq!(result, 30);
//! \`\`\`
```

这里的内容描述的是整个 Library Crate，而不是某一个具体函数。

在模块文件中也可以使用 `//!`：

```
//! 用户认证模块。
//!
//! 该模块提供用户登录、退出和密码验证功能。

pub fn login() {
    println!("用户登录");
}
```

可以简单记住：

```
/// 描述后面的代码项
//! 描述当前模块或 Crate
```

## 文档注释支持 Markdown

Rust 文档注释支持常用 Markdown 语法。

## 标题

```
/// # 功能说明
///
/// # 参数
///
/// # 返回值
```

## 列表

```
/// 支持以下功能：
///
/// - 创建用户
/// - 查询用户
/// - 删除用户
```

## 加粗和行内代码

```
/// 当用户名为空时返回 **错误**。
///
/// 参数 \`name\` 不能是空字符串。
```

## 代码块

```
/// # 示例
///
/// \`\`\`
/// let number = 10;
/// println!("{}", number);
/// \`\`\`
```

良好的 Markdown 结构可以让生成的 API 文档更加清晰。

## 为函数编写完整文档

一个较完整的函数文档通常包括：

- • 简要说明
- • 参数
- • 返回值
- • 错误
- • Panic 情况
- • 使用示例

例如：

```
/// 计算两个整数相除的结果。
///
/// # 参数
///
/// - \`a\`：被除数
/// - \`b\`：除数
///
/// # 返回值
///
/// 成功时返回相除结果。
///
/// # 错误
///
/// 当 \`b\` 等于 \`0\` 时返回错误信息。
///
/// # 示例
///
/// \`\`\`
/// let result = safe_divide(10, 2);
/// assert_eq!(result, Ok(5));
/// \`\`\`
pub fn safe_divide(
    a: i32,
    b: i32,
) -> Result<i32, String> {
    if b == 0 {
        return Err(String::from("除数不能为 0"));
    }

    Ok(a / b)
}
```

需要特别注意：文档中的代码块不仅用于展示，还可以作为测试执行。

## 文档测试 Doctest

Rust 会把文档中的 Rust 代码示例当成测试代码。

例如：

```
/// 计算两个整数的和。
///
/// # 示例
///
/// \`\`\`
/// let result = add(2, 3);
/// assert_eq!(result, 5);
/// \`\`\`
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

执行：

```
cargo test
```

Cargo 会同时运行普通测试和文档测试。

文档测试可以保证：

> 文档中的示例不是过期代码，而是真正可以编译和运行的代码。

## Library Crate 中的文档示例

在真实的库项目中，文档示例通常需要导入 Crate。

假设 Cargo.toml 中的包名为：

```
[package]
name = "math-utils"
```

Rust 代码中使用的 Crate 名称通常是：

```
math_utils
```

文档可以写成：

```
/// 计算两个整数的和。
///
/// # 示例
///
/// \`\`\`
/// use math_utils::add;
///
/// let result = add(10, 20);
///
/// assert_eq!(result, 30);
/// \`\`\`
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

Cargo 包名中的连字符：

```
math-utils
```

在 Rust 路径中通常写成下划线：

```
math_utils
```

## 隐藏示例中的辅助代码

有些代码是示例运行所必需的，但没有必要展示给文档读者。

可以在代码行前添加：

```
#
```

例如：

```
/// # 示例
///
/// \`\`\`
/// # fn main() -> Result<(), String> {
/// let result = safe_divide(10, 2)?;
///
/// assert_eq!(result, 5);
/// # Ok(())
/// # }
/// \`\`\`
pub fn safe_divide(
    a: i32,
    b: i32,
) -> Result<i32, String> {
    if b == 0 {
        Err(String::from("除数不能为 0"))
    } else {
        Ok(a / b)
    }
}
```

以 `#` 开头的行会参与测试，但通常不会显示在最终文档示例中。

---

## 标记不运行的代码

某些示例只用于说明语法，不适合真正执行。

可以使用：

```
/// \`\`\`no_run
/// std::fs::remove_file("important.txt")?;
/// # Ok::<(), std::io::Error>(())
/// \`\`\`
```

`no_run` 表示：

- • 代码需要通过编译
- • 但测试时不实际运行

如果代码故意不能编译，可以使用：

```
/// \`\`\`compile_fail
/// let number: i32 = "Rust";
/// \`\`\`
```

如果只是普通文本，不需要当成 Rust 代码，可以使用：

```
/// \`\`\`text
/// GET /api/users
/// \`\`\`
```

## 为结构体编写文档

结构体和字段都可以添加文档。

```
/// 系统用户信息。
#[derive(Debug)]
pub struct User {
    /// 用户唯一编号。
    pub id: u64,

    /// 用户显示名称。
    pub name: String,

    /// 用户是否处于启用状态。
    pub enabled: bool,
}
```

如果字段是公开的，建议为每个字段说明其作用。

创建方法也应该添加文档：

```
impl User {
    /// 创建一个新的启用用户。
    ///
    /// # 示例
    ///
    /// \`\`\`
    /// use user_lib::User;
    ///
    /// let user = User::new(1, "Tom");
    ///
    /// assert_eq!(user.name, "Tom");
    /// assert!(user.enabled);
    /// \`\`\`
    pub fn new(id: u64, name: &str) -> Self {
        Self {
            id,
            name: name.to_string(),
            enabled: true,
        }
    }
}
```

## 为枚举编写文档

```
/// 订单当前状态。
#[derive(Debug)]
pub enum OrderStatus {
    /// 订单已经创建，但尚未支付。
    Pending,

    /// 订单已经完成支付。
    Paid,

    /// 订单已经取消。
    Cancelled,
}
```

公开枚举的每个变体都应该有明确说明，尤其是业务状态枚举。

## 生成项目文档

在项目根目录执行：

```
cargo doc
```

Cargo 会：

1. 1\. 编译当前项目
2. 2\. 解析文档注释
3. 3\. 生成 HTML 文档
4. 4\. 保存到 `target/doc` 目录

生成完成后，可以手动打开：

```
target/doc/项目名称/index.html
```

---

## 生成并打开文档

更常用的命令是：

```
cargo doc --open
```

它会在生成完成后尝试使用默认浏览器打开文档首页。

适合在开发过程中快速检查文档效果。

---

## 不生成依赖文档

默认情况下，Cargo 可能也会为依赖生成文档。

如果只想查看当前项目，可以使用：

```
cargo doc --no-deps
```

结合自动打开：

```
cargo doc --no-deps --open
```

这样生成速度通常更快，文档目录也更加简洁。

---

## 生成私有内容文档

默认情况下，文档主要展示公共 API。

如果开发阶段需要查看私有函数和私有模块，可以执行：

```
cargo doc --document-private-items
```

这对于检查项目内部模块关系很有帮助，但对外发布的库文档通常只需要公开 API。

---

## 文档中的链接

可以在文档中引用其他类型或函数：

```
/// 创建一个 [\`User\`]。
///
/// 创建完成后可以调用 [\`User::disable\`] 禁用该用户。
pub fn create_user() -> User {
    User::new(1, "Tom")
}
```

这种链接称为文档内部链接。

生成文档后， `User` 和 `User::disable` 会变成可以点击的链接，方便读者跳转。

---

## 查看标准库文档

Rust 标准库本身也使用 rustdoc 生成文档。

在学习以下类型时：

```
Vec
String
HashMap
Option
Result
```

都可以通过标准库文档查看：

- • 类型定义
- • 方法列表
- • Trait 实现
- • 示例代码

本地安装的 Rust 文档可以通过下面的命令打开：

```
rustup doc
```

这在网络不稳定时非常实用。

## 实战：为数学工具库生成文档

项目结构：

```
math-utils
├── Cargo.toml
└── src
    └── lib.rs
```

`src/lib.rs` ：

```
//! 一个简单的数学工具库。
//!
//! 提供基础加法和安全除法功能。

/// 计算两个整数的和。
///
/// # 示例
///
/// \`\`\`
/// use math_utils::add;
///
/// assert_eq!(add(10, 20), 30);
/// \`\`\`
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}

/// 安全地计算两个整数相除的结果。
///
/// # 错误
///
/// 当除数为 \`0\` 时返回错误。
///
/// # 示例
///
/// \`\`\`
/// use math_utils::divide;
///
/// assert_eq!(divide(10, 2), Ok(5));
/// assert!(divide(10, 0).is_err());
/// \`\`\`
pub fn divide(
    a: i32,
    b: i32,
) -> Result<i32, String> {
    if b == 0 {
        return Err(String::from("除数不能为 0"));
    }

    Ok(a / b)
}
```

运行测试：

```
cargo test
```

生成文档：

```
cargo doc --no-deps --open
```

这样就得到了一个包含介绍、API 说明和可执行示例的完整库文档。

## 常见错误

## 使用普通注释代替文档注释

错误：

```
// 创建用户
pub fn create_user() {}
```

这不会出现在 API 文档中。

正确：

```
/// 创建用户。
pub fn create_user() {}
```

---

## 文档示例无法编译

文档中写了已经删除或修改的 API：

```
/// \`\`\`
/// old_function();
/// \`\`\`
```

执行 `cargo test` 时，文档测试会失败。

因此每次修改公共 API 后，也应该同步更新文档。

---

## 只说明“做什么”，不说明失败情况

不完整：

```
/// 读取配置文件。
```

更完整：

```
/// 读取配置文件。
///
/// # 错误
///
/// 当文件不存在、权限不足或内容无法读取时返回错误。
```

对于返回 `Result` 的公共函数，应尽量说明可能的错误。

---

## 文档与实际行为不一致

例如文档说：

```
空数组返回 0
```

但代码实际会触发 panic。

错误文档比没有文档更加危险。

文档示例和测试可以减少这种问题。

---

## Rust 文档最佳实践

## 为所有公共 API 编写文档

凡是使用：

```
pub
```

公开的函数、结构体、枚举和 Trait，都应该说明用途。

## 示例尽量可以直接运行

比起只写概念说明，完整示例更容易让使用者理解 API。

## 说明错误和 Panic

返回 `Result` 时添加：

```
# Errors
```

可能 panic 时添加：

```
# Panics
```

## 保持文档和代码同步

修改函数参数、返回值或行为时，应同时修改文档和示例。

## 使用 cargo test 检查文档

文档不仅是说明，也应该是可验证的代码。
